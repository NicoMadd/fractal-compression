Fractal Codebook

This document describes the Fractal Codebook ASCII file format: a list of range–domain affine mappings (one per range block), as loaded by implementations.java.compression.src.utils.fractal.mapping.Codebook. On disk the format begins with the two-byte magic FC (Fractal Codebook). The layout is intentionally similar in spirit to ASCII PGM (PGMA): a short magic token, then decimal numbers separated by whitespace.

Definition

  • Magic number. The first two bytes are the ASCII characters F and C, the on-disk signature for a Fractal Codebook file.
  • Header line. After the magic, leading whitespace is skipped (same idea as SequenceReader.skipFollowingWhitespaces). The remainder of the same line up to and not including the first line feed (\n) must contain exactly three integer tokens, separated by whitespace:
    1. rangeSize — edge length in pixels of each range block (RBD).
    2. domainSize — edge length in pixels of each domain block (DBD).
    3. N — number of mapping records that follow.
    The reference implementation reads this line as text, trims it, splits on runs of whitespace, and requires exactly three fields. Values are parsed with Integer.parseInt. The reader consumes bytes until the first \n (Unix \n or CRLF both work: the third token is trimmed).
  • Mapping records. For each of the N rows, six tokens in order, each separated by whitespace:
    1. rangeX — decimal int, x-coordinate of the range block’s top-left pixel.
    2. rangeY — decimal int, y-coordinate of the range block’s top-left pixel.
    3. domainX — decimal int, x-coordinate of the domain block’s top-left pixel.
    4. domainY — decimal int, y-coordinate of the domain block’s top-left pixel.
    5. s — decimal float, contrast (scale) coefficient in the affine map value ≈ s × sample + o (see compressor implementation for exact use).
    6. o — decimal float, offset (brightness) coefficient.
    These fields match the Java record FractalMapping(int rangeX, int rangeY, int domainX, int domainY, float s, float o).
  • Encoding. Integers use Integer.parseInt semantics; floats use Float.parseFloat (locale-independent ASCII digits, optional sign and exponent). After the header line, line breaks are optional between tokens; any run of whitespace separates tokens.

Decoder contract. rangeSize and domainSize in the header must match the compressor settings used to build the file; decoders should use them (or verify against CLI / pipeline parameters) so domain and range windows align with stored coordinates. Image width, height, and iteration count are not stored in the codebook.

Example Fractal Codebook file

Three mappings with range blocks of side 4, domain blocks of side 8, and illustrative affine rows (numbers only for documentation): 

FC 4 8 3
0 0 16 16 0.92 4.5
4 0 32 0 1.0 0.0
0 4 0 32 0.88 -2.0

Characteristics

  • ASCII text (human-inspectable, not binary-packed)
  • One codebook per file
  • No built-in comments line (unlike PGM #); entire file is tokens after the magic
  • Typical extension: .fc or any path passed to new Codebook(String path)

Implementation reference

  • Codebook.deserialize — read magic; skip leading whitespace; read first line as rangeSize domainSize N; then N mappings via readMapping.
  • Codebook.serializeMetadata — write FC, space, rangeSize, space, domainSize, space, N, line break.
  • Codebook.readMapping — six tokens per FractalMapping.
  • Codebook.rangeSize() / domainSize() — accessors for header geometry after load.
  • SequenceReader.readNextInt / readNextFloat — tokenization for mapping rows.
